Kubeat is installed.

Sign in as "admin" with the password
{{- if .Values.auth.existingSecret }}
  taken from the Secret "{{ .Values.auth.existingSecret }}" (key "password").
{{- else }}
  kubectl -n {{ .Release.Namespace }} get secret {{ .Release.Name }}-admin -o jsonpath='{.data.password}' | base64 -d; echo
{{- end }}
Then create the other accounts under "Kullanıcılar".

Open the UI:
{{- if .Values.route.enabled }}
{{- with include "kubeat.publicURL" . }}
  {{ . }}
{{- else }}
  through the Route "{{ .Release.Name }}".
{{- end }}
{{- else if .Values.ingress.enabled }}
  {{ include "kubeat.publicURL" . | default (printf "through the Ingress %q" .Release.Name) }}
{{- if include "kubeat.ingressTLS" . }}
  The Ingress serves it over HTTPS with the certificate in the Secret
  "{{ include "kubeat.ingressTLSSecret" . }}"; create the Secret, or let cert-manager make it
  (see ingress.annotations).
{{- if not (lookup "v1" "Secret" .Release.Namespace (include "kubeat.ingressTLSSecret" .)) }}

WARNING: the Secret "{{ include "kubeat.ingressTLSSecret" . }}" does not exist yet. That is expected while
cert-manager is issuing it. Otherwise create it (type kubernetes.io/tls), or,
for an Ingress without TLS, upgrade with ingress.tls.enabled=false. Until
then the ingress controller serves its own default certificate or plain
HTTP, and over plain HTTP browsers drop the session cookie, which is Secure
for an https:// address: nobody can sign in.
{{- end }}
{{- else }}

WARNING: the Ingress has no TLS. Unless TLS ends in front of the ingress
controller, passwords and session tokens cross the network in clear text.
Where it does, publicURL must be the https:// address.
{{- if .Values.oidc.issuer }}
SSO needs HTTPS in front of the ingress controller: the identity provider
sends users back to an https:// address. Without it, end TLS somewhere or
turn SSO off (leave oidc.issuer empty).
{{- end }}
{{- end }}
{{- else }}
  kubectl -n {{ .Release.Namespace }} port-forward svc/{{ .Release.Name }}-frontend 3000:3000
  then http://localhost:3000
{{- end }}
{{- if .Values.oidc.issuer }}

SSO sends users back to this address; register exactly it with the
identity provider:
  {{ . }}
{{- if and $.Values.publicURL (not $.Values.oidc.redirectURL) }}

{{- else }}

SSO is configured, but no address of Kubeat is known to send users back

{{- end }}
{{- if include "kubeat.metricsAuth" . }}

/metrics answers only scrapes that present the token in the Secret
"{{ include "kubeat.metricsTokenSecret" . }}" (key "token") as a bearer token.
{{- if .Values.metrics.serviceMonitor.enabled }}
The ServiceMonitor sends it; a Prometheus configured by hand must send it too.
{{- else }}
A Prometheus configured by hand must send it (authorization.credentials_file
in the scrape configuration), or install with metrics.auth.enabled=false.
To read it:
  kubectl -n {{ .Release.Namespace }} get secret {{ include "kubeat.metricsTokenSecret" . }} -o jsonpath='{.data.token}' | base64 -d; echo
{{- end }}
{{- end }}

{{- if and (contains ":9091" .Values.prometheus.url) .Values.discovery.enabled (not .Values.discovery.namespaces) (not .Values.prometheus.openshiftMonitoringView) }}

WARNING: prometheus.url is on port 9091, where OpenShift's Thanos Querier
answers queries across the cluster, and only to service accounts with
cluster-monitoring-view. Set prometheus.openshiftMonitoringView=true, or the
pods' CPU and memory stay empty. The discovery role no longer grants "get"
on namespaces, which OpenShift 4.14 and older accepted there instead.
{{- end }}
{{- if and .Values.prometheus.url .Values.prometheus.tokenFile .Values.prometheus.insecureSkipVerify }}

WARNING: prometheus.insecureSkipVerify is set together with
prometheus.tokenFile: the service account token goes to
  {{ .Values.prometheus.url }}
without its certificate being checked, so whoever answers there gets it.
Set prometheus.caFile instead.
{{- end }}
